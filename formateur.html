Site des mandats pratiques

Mode d'emploi formateur : mettre à jour le site sans toucher au code

Gil Charmillot · version du 13.10.2026 · cette page est mise à jour en même temps que le site

Le site (apprentis)gilgeneva-png.github.io/mandats-pratiques
Le dépôt (formateur)github.com/gilgeneva-png/mandats-pratiques
Un seul fichier à modifier : mandats.yml. Tout le site en découle : planning, pages des MP, compte à rebours, fichiers agenda. Le reste du dépôt ne se touche jamais.

1Modifier le site

  1. Ouvrir le dépôt sur github.com et se connecter.
  2. Cliquer sur le fichier mandats.yml.
  3. Cliquer sur l'icône crayon, en haut à droite du fichier. Le texte devient modifiable.
  4. Retrouver le passage avec Ctrl+F (Cmd+F sur Mac), par exemple en tapant l'id du MP : b2-mandat.
  5. Modifier, puis cliquer sur le bouton vert Commit changes, et confirmer dans la fenêtre.
  6. Attendre une à deux minutes, puis recharger le site pour vérifier.

2Les trois règles pour ne rien casser

Les espaces

Les espaces en début de ligne donnent la structure. Ne pas les supprimer ni utiliser la touche Tab.

Les dates

Toujours au format année-mois-jour : 2026-12-04.

Les guillemets

Un texte court qui contient « : » se met entre guillemets : "Note : à rendre".

Pour les textes longs (consignes), tout est permis après la ligne qui se termine par |, à condition de garder le même décalage à gauche.

4En cas d'erreur

Message rouge sur le site. Il indique le numéro de la ligne fautive dans mandats.yml. Corriger cette ligne (le plus souvent : un espace en trop ou en moins, ou des « : » sans guillemets), puis recommiter.
Avertissement « À corriger ». Une date de rendu tombe après le dernier rendu du semestre (22.12), ou un MP n'a pas de date. Le site fonctionne, mais l'incohérence est signalée.

Revenir en arrière : sur la page de mandats.yml, cliquer sur History, ouvrir la version précédente, copier son contenu et le recoller dans l'éditeur.

5Préparer le semestre suivant

Le semestre suivant se prépare dans un fichier brouillon, dans le même dépôt : mandats-S6.yml. Les apprentis ne le voient pas.

FichierQui le voit, et à quelle adresse
mandats.ymlLes apprentis : le semestre en cours.
gilgeneva-png.github.io/mandats-pratiques/
mandats-S6.ymlLe formateur seul, en aperçu, avec un bandeau jaune « brouillon ».
gilgeneva-png.github.io/mandats-pratiques/?fichier=mandats-S6.yml

Pendant la préparation

  • Modifier mandats-S6.yml sur GitHub, comme mandats.yml.
  • Vérifier le résultat avec l'adresse d'aperçu, à garder en favori.
  • Créer un dossier Drive pour les MP du semestre, à côté du dossier du semestre en cours, jamais à l'intérieur : sur Drive, le partage d'un dossier s'applique à tout ce qu'il contient.
  • Coller le lien de ce dossier dans dossier_pdf. Ne le partager avec les apprentis qu'au changement de semestre.
  • Passer chaque MP de proposition à valide une fois la consigne arrêtée.

Le jour du changement

  1. Renommer mandats.yml en mandats-S5.yml (crayon, modifier le nom en haut, Commit). C'est l'archive.
  2. Renommer mandats-S6.yml en mandats.yml.
  3. Recharger le site : les apprentis voient le nouveau semestre.
  4. Sur Drive, partager le dossier du nouveau semestre (accès restreint, lecture seule) et retirer les accès de l'ancien si le groupe change.

L'ancien semestre reste consultable avec ?fichier=mandats-S5.yml.

Le nom d'un brouillon est libre (lettres, chiffres, tirets), tant qu'il se termine par .yml.

6Deuxième groupe

  • Ajouter le groupe dans groupes: avec l'id g2.
  • Dans chaque MP, ajouter une ligne g2: avec ses dates.
  • Si la consigne diffère, utiliser variantes: (exemple dans le fichier).
  • Un menu « Mon groupe » apparaît alors automatiquement sur le site.

7La page « Comment je suis évalué·e »

Son contenu est dans le fichier evaluation.yml, qui se modifie exactement comme mandats.yml (crayon, Commit). Il ne dépend pas du semestre.

  • intro : le texte d'ouverture.
  • note_officielle : la barre 50 / 50 et le détail des deux blocs (part = pourcentage affiché).
  • sections : chaque section a un titre, un texte et éventuellement des points (cartes), chacun avec compte_dans pour indiquer le critère officiel concerné.
  • glossaire : les mots à connaître (DCO, CO, MP…).

Adresse : gilgeneva-png.github.io/mandats-pratiques/eval.html. Elle est liée depuis l'accueil et depuis chaque page de MP.

8Bon à savoir

  • Thèmes : chaque apprenti choisit l'ambiance du site (Classique, Soirée, Ferme, Plage, Banque, Sport, Arcade) en haut de l'accueil ou en bas d'une page. Le choix reste sur son appareil et ne change rien au contenu.
  • Accessibilité : le thème Arcade est conçu pour rester lisible avec un daltonisme (couleurs distinctes, un symbole de manette par MP). Le bouton Mes réglages fonctionne avec tous les thèmes : couleurs bien distinctes (avec symboles), texte plus grand, titres simples (sans police fantaisie), sans animation. Partout, le mot-clé de chaque MP est écrit sur le planning : aucune information ne passe par la couleur seule. Rien à configurer côté formateur.
  • Fichiers agenda : si une date change après qu'un apprenti a importé le fichier agenda, son agenda ne se met pas à jour. Lui demander de réimporter.
  • Checklist « Avant de rendre » : les coches restent sur le téléphone de l'apprenti. Le formateur n'y a pas accès.
  • Site public : il ne doit contenir aucun nom ni aucune donnée d'apprenti. Les PDF officiels restent protégés sur le Drive institutionnel.
  • Ouvrir index.html sur l'ordinateur ne fonctionne pas : le site ne marche qu'en ligne.

9Mettre à jour le site lui-même

Quand une fonction ou le design change, une archive .zip est livrée. Elle ne contient jamais mandats.yml ni les brouillons : le contenu n'est pas touché.

  1. Décompresser l'archive.
  2. Dans le dépôt, rester à la racine (ne pas entrer dans assets), puis Add file, Upload files.
  3. Glisser tout le contenu de l'archive d'un coup. GitHub conserve les sous-dossiers.
  4. Commit changes, puis recharger le site avec Ctrl+Maj+R.

Contenu normal de la racine du dépôt : index.html, mp.html, eval.html, formateur.html, mandats.yml, evaluation.yml, les brouillons (mandats-S6.yml…), README.md et le dossier assets. Un fichier en trop (doublon) se supprime : l'ouvrir, « … » en haut à droite, Delete file, Commit.
